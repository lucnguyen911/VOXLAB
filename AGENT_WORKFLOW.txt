PROJECT CONTEXT
======================================================================

PROJECT_NAME:
VoxLab

INITIAL_IDEA:
VoxLab là ứng dụng desktop webview chạy local, tập trung vào xử lý chuyển văn bản thành giọng nói và văn bản
bằng các model AI local.

TARGET_PLATFORM:
Mục tiêu chính của VoxLab là cho phép người dùng thực hiện trong một ứng dụng:

- Text-to-Speech (TTS) bằng nhiều model local.
- Voice cloning/reference voice nếu model hỗ trợ.
- Transcribe audio/video thành văn bản bằng local ASR.
- Tự động chuẩn hóa văn bản trước khi TTS:
  - Unicode normalization;
  - tối ưu khoảng trắng;
  - chuẩn hóa dấu câu;
  - sentence segmentation;
  - text cleanup.
- Có chế độ AI hỗ trợ sửa dấu câu và tối ưu văn bản trước TTS nhưng không được
  tự ý thay đổi ý nghĩa nội dung nếu người dùng không yêu cầu.
- Dịch văn bản bằng model local.
- Chia văn bản thành chunk thông minh trước khi TTS.
- Quản lý hàng đợi generation.
- Hiển thị progress.
- Hỗ trợ Cancel / Retry.
- Ghép các chunk audio thành file audio hoàn chỉnh.
- Quản lý output và các file được tạo.
- Cho phép cấu hình model và các tham số phù hợp với phần cứng người dùng.
- Hoạt động tốt trên nhiều cấu hình máy từ yếu đến mạnh.
- Ưu tiên xử lý local, không phụ thuộc cloud cho các chức năng cốt lõi.
- Thiết kế sao cho có thể bổ sung model mới sau này mà không phải rewrite toàn bộ app.

Các model/runtime hiện đang được cân nhắc, chưa mặc định tất cả phải nằm trong MVP:

TTS candidates:
- OmniVoice
- Chatterbox family
- Qwen3-TTS family
- các local TTS model khác nếu feasibility check cho thấy phù hợp.

Transcription:
- faster-whisper làm runtime/engine ưu tiên.
- sử dụng các model Whisper phù hợp theo cấu hình phần cứng.

Text AI / punctuation / translation:
- ưu tiên local LLM thông qua LM Studio hoặc runtime local tương đương.
- Qwen3.5 là candidate chính cho punctuation, text optimization và translation.
- có thể đánh giá model chuyên dịch khác nếu thực sự đem lại lợi ích.

Text normalization không cần AI khi có thể xử lý chính xác bằng deterministic code.

Trước khi chốt SPEC và architecture, Agent phải thực hiện feasibility check đối
với các model/runtime quan trọng và xác định:
- dependency;
- license;
- CPU/GPU support;
- RAM/VRAM;
- Python/runtime compatibility;
- model loading/unloading;
- packaging feasibility;
- dependency conflict;
- performance risk.

Các giá trị như:
- chunk size;
- concurrency;
- worker count;
- batch size;
- model unload timeout;
- buffer;
không được chốt bằng phỏng đoán.
Nếu cần phải đánh dấu TUNING REQUIRED và benchmark sau.

TARGET_PLATFORM:
Windows desktop là nền tảng chính cho phiên bản đầu tiên.

Ưu tiên:
- Windows 10/11 64-bit.
- Hỗ trợ cả máy chỉ dùng CPU và máy có GPU NVIDIA khi khả thi.
- Có hardware detection/profile để lựa chọn model hoặc cấu hình phù hợp.
- MVP không bắt buộc hỗ trợ macOS/Linux, nhưng architecture không được tạo
  dependency Windows-specific không cần thiết nếu có thể tránh.

PREFERRED_STACK:
Desktop application:
- Tauri
- React
- TypeScript

Frontend:
- React + TypeScript.

Native/Desktop layer:
- Tauri / Rust.

Local AI/model integration:
- Model engine chạy tách khỏi UI bằng service/worker/process boundary phù hợp.
- Không để React frontend gọi trực tiếp model runtime.

TTS:
- runtime/model-specific adapter.
- Agent tự xác định Python/runtime/environment phù hợp sau Model Feasibility Check.

Transcription:
- faster-whisper là candidate engine mặc định.
- model Whisper được lựa chọn theo hardware profile.

Text AI:
- LM Studio local API là candidate chính cho local LLM integration.
- architecture không được phụ thuộc cứng vào duy nhất LM Studio nếu abstraction
  đơn giản có thể tránh được việc đó.

Storage:
- Agent đề xuất giải pháp local đơn giản phù hợp sau khi requirement được làm rõ.
- Không thêm database phức tạp nếu chưa cần.

Architecture principle:
- local-first;
- modular model adapters;
- model loading on demand;
- không load tất cả model cùng lúc;
- ưu tiên dependency isolation khi các model có runtime conflict;
- không thiết kế universal AI framework quá mức;
- chỉ tạo abstraction đủ để hỗ trợ các engine thực sự được chọn cho VoxLab.

======================================================================
8. DEBUGGING WORKFLOW
======================================================================

Trigger when a bug/error/log/symptom appears.
Do not create a new full Plan unless root cause requires major architecture or
approved-scope change.

Workflow:
1. Read complete relevant error/log.
2. Reproduce when possible.
3. Isolate failure location.
4. Separate symptom from root cause.
5. Generate hypotheses ordered by likelihood.
6. Test hypotheses using code/logs/tests/reproduction.
7. Identify most supported root cause.
8. Apply smallest correct fix.
9. Rerun failing scenario.
10. Run relevant regression tests.
11. Check collateral damage.

Do not disable tests, remove validation, broad-catch failures, hard-code a
workaround, or rewrite unrelated code.

Output:
ROOT CAUSE
EVIDENCE
FIX
FILES CHANGED
FAILING CASE AFTER FIX
REGRESSION RESULT
RECURRENCE RISK
